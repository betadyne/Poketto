# AGENTS.md - Poketto Repository Guide

Scope: This file governs the entire repository.

Read this first if you're contributing, reviewing, or acting as an automated coding agent.

## Project Overview

**Poketto** is a Visual Novel Game Launcher built with:
- **Frontend**: SolidJS + TypeScript + TailwindCSS v4
- **Backend**: Tauri v2 + Rust
- **Database**: redb (embedded key-value store)
- **APIs**: VNDB API integration, Discord Rich Presence

## Reading Order

1. This file (AGENTS.md)
2. `src-tauri/src/lib.rs` (Rust entry point and command registration)
3. `src/App.tsx` (Frontend entry point)
4. GitHub Issues: https://github.com/betadyne/Poketto/issues

## Intent & Principles

- **SOLID, KISS, YAGNI** - Keep it simple and avoid over-engineering
- **Cross-platform first**: Support Windows and Linux (Wine/Proton)
- **Offline-capable**: Core functionality works without internet
- **Type-safe IPC**: Use tauri-specta for auto-generated TypeScript bindings
- **Testability**: Modular boundaries, pure functions where possible
- **Clarity**: Idiomatic Rust/TypeScript naming, minimal comments

## Expectations for Agents/Contributors

- Skim `src-tauri/src/lib.rs` for backend architecture context before coding
- Drive all planning via GitHub Issues (no in-repo trackers)
- Keep changes small and focused; one feature per PR
- Run `pnpm tauri dev` to test changes before committing
- If behavior/architecture changed, update this AGENTS.md in the same commit

## Session Handoff Protocol (GitHub Issues)

- **Start**: Pick a ready P0 issue, self-assign, post a "Session Start" plan

### File Layout Rules

- **One component per file**: Each React/Solid component in its own file
- **Commands by domain**: Rust commands grouped by feature in `src-tauri/src/commands/`
- **Auto-generated bindings**: `src/bindings.ts` is generated by tauri-specta, never edit manually
- **Contexts for state**: Use SolidJS contexts in `src/context/` for global state

## Workflow & Quality

### Development Commands

```bash
pnpm install
pnpm tauri dev
pnpm tauri build
pnpm tsc --noEmit
cargo check
cargo clippy
```

### Code Quality Rules

- TypeScript bindings are auto-generated - run `pnpm tauri dev` to regenerate
- Use structured types from `src/bindings.ts` for IPC communication
- Handle errors gracefully; show user-friendly messages
- Never commit secrets or tokens (`.env` is gitignored)
- Keep the repo clean: generated artifacts are in `.gitignore`

### Priority Labels

- **P0**: Critical - blocks release or core functionality
- **P1**: High - important feature or significant bug
- **P2**: Medium - nice to have, can wait

## Coding Standards

### TypeScript/SolidJS (Frontend)

- Use SolidJS primitives: `createSignal`, `createEffect`, `createMemo`
- Prefer `Show`, `For`, `Switch/Match` for conditional rendering
- Type all props and return values
- Use `async/await` for async operations
- Naming: `camelCase` for variables/functions, `PascalCase` for components

### Rust (Backend)

- Use `Result<T, E>` for fallible operations
- Define custom error types in `error.rs`
- Use `#[tauri::command]` for IPC handlers
- Register new commands in `lib.rs` with tauri-specta
- Naming: `snake_case` for functions/variables, `PascalCase` for types

### Adding New Commands (Rust -> TypeScript)

1. Add command function in appropriate `src-tauri/src/commands/*.rs` file
2. Register in `lib.rs` under `tauri_specta::collect_commands![]`
3. Run `pnpm tauri dev` to regenerate `src/bindings.ts`
4. Import and use from `src/bindings.ts` in frontend

## Git Workflow

### Branch Strategy

- `main` - stable release branch
- Feature branches: `feature/<name>`
- Bug fixes: `fix/<name>`

### Commit Message Format

```
<type>: <short description>

[optional body]
```

Types: `feat`, `fix`, `docs`, `refactor`, `chore`, `test`

### Pull Request Guidelines

1. Create feature branch from `main`
2. Make changes, test locally with `pnpm tauri dev`
3. Commit with descriptive messages
4. Push and create PR via GitHub
5. Link related issues

## Ambiguity Resolution

- Prefer the simplest design that satisfies current requirements
- When in doubt, follow existing patterns in the codebase
- User instructions take precedence over this document
- Ask for clarification rather than making assumptions
