# Product Requirement Document (PRD)

## Project: Poketto (Tauri Visual Novel Launcher)

Poketto is a cross-platform Visual Novel game launcher built on
**Tauri v2 + SolidJS + Rust**. This repository is purely the Tauri
application; the experimental pure-Rust/Slint rewrite lives in a separate
repository and leaves no trace here (no `crates/` workspace, no Slint
references, no root Cargo workspace).

### 1. Objective & Scope

A fast, offline-capable library client for visual novels on Linux and
Windows that preserves the full shipped feature set:

1. VNDB metadata fetching, search, and caching (details, characters,
   authenticated user list and votes).
2. Local library management (add/edit/remove/hide local games, per-game
   settings, completion flags).
3. Linux runtime support (Wine prefix and Steam Proton runner detection,
   per-game and global Wine settings).
4. Game process launching with playtime tracking (total + daily).
5. Discord Rich Presence with configurable buttons.
6. NSFW blur gating, in-app logs viewer, auto-updater.

### 2. Tech Stack

#### A. Frontend (`src/`, `index.html`, `vite.config.ts`)

- **Framework:** `solid-js` + `@solidjs/router` (routes: Library, Detail,
  Settings, Logs)
- **Styling:** `tailwindcss` v4 via `@tailwindcss/vite` plus theme tokens
  in `src/index.css` (`--color-*`: light theme, navy `--color-accent`
  `#000080`, local Nunito Sans `@font-face` from `public/fonts/`)
- **Icons:** `@tabler/icons-solidjs` 3.x ONLY (SolidJS port of Tabler; no `lucide-solid`, no `@tabler/icons-react`)
- **State:** SolidJS context providers (`GameContext`, `SettingsContext`,
  `VndbContext`) + fine-grained signals/memos; `@solid-primitives/storage`
- **Generated contract:** `src/bindings.ts` (auto-generated by
  tauri-specta in debug builds; NEVER hand-edit), re-exported through
  `src/types.ts` (plus local payloads such as `GameExitedPayload`)
- **Tests:** `vitest` (`src/utils/*.test.ts`: blur, formatters,
  validators; `src/api/wine.test.ts`: Wine invoke wrappers)

#### B. Backend (`src-tauri/`)

- **Framework:** `tauri` v2 (`tauri-build`, `generate_context!`)
- **IPC typing:** `tauri-specta` + `specta` + `specta-typescript`
- **Async:** `tokio` (`rt-multi-thread`, `sync`, `process`, `macros`)
- **HTTP:** `reqwest` 0.13 with `default-features = false` plus `rustls`,
  `json`, `http2` (rustls platform-verifier TLS, no OpenSSL from our
  direct client)
- **Storage:** `rusqlite` `bundled` (`poketto.db`: `games`,
  `playtime_sessions`, `vndb_cache`) + JSON settings files
- **Discord:** `discord-rich-presence` (pinned git rev)
- **Sync:** `parking_lot::Mutex`
- **Plugins:** dialog, fs, shell, updater, process, log

#### C. Tooling

- **Package manager:** npm (`package-lock.json` committed)
- **Rust:** stable via `rust-toolchain.toml` (`clippy`, `rustfmt`); MSRV
  1.77.2 per `src-tauri/Cargo.toml`
- **Dev profile:** `[profile.dev] incremental = true`; no blanket
  `opt-level` overrides (fast iteration over dev-binary speed)
- **Bundling:** NSIS target, updater artifacts with GitHub release
  endpoint (`tauri.conf.json`)

### 4. Data Architecture

Data directory (per-platform app data dir):

| File              | Format | Content                                              |
| ----------------- | ------ | ---------------------------------------------------- |
| `poketto.db`      | SQLite | `games` (library source of truth), `playtime_sessions` (per-session log, FK cascade), `vndb_cache` (`vn:`/`chars:` JSON payloads), `schema_meta` (one-time import flag) |
| `settings.json`   | JSON   | `AppSettings` (token, blur, Discord, Wine defaults)  |
| `daily_playtime.json` | JSON | `DailyPlaytimeData` (`game -> date -> minutes`)   |

Cache hierarchy for VNDB reads: in-memory `HashMap` (`vn_mem_cache`,
`char_mem_cache`) -> SQLite disk cache -> network. Writes persist
atomically (SQLite transactions; `atomic_write` via temp file + rename
for JSON).

Core domain types (`models.rs`):

- `GameMetadata`: id, title, path, vndb_id, cover_url, play_time
  (minutes), is_finished, last_played, is_hidden, show_spoilers,
  game_type, wine_settings.
- `AppSettings`: vndb_token, vndb_user_id, blur_nsfw, discord flags and
  buttons, default_wine_prefix/binary, use_steam_runtime.
- Wine: `WineType` (Proton, ProtonGE, Wine, ...), `WineSource`, `GameType`,
  `WineVersion` (name, binary_path, lib_path, version), `WineSettings`
  (per-game prefix/runner/env vars, `use_global_prefix`).
- VNDB: search results, VN details (tags, producers, developers, image),
  characters + traits, user list items, labels, auth info.

### 5. IPC Contract (Tauri Commands + State)

Backend exposes typed commands via `#[tauri::command]` +
`#[specta::specta]`, registered in `collect_commands!` and exported to
`../src/bindings.ts` on debug builds:

- **Library:** `init_app`, `get_all_games`, `add_local_game`,
  `remove_game`, `update_game`, `set_game_hidden`.
- **VNDB:** `search_vndb`, `fetch_vndb_detail`, `fetch_vndb_characters`,
  `clear_vndb_cache`, `clear_all_cache`, `save_vndb_token`,
  `clear_vndb_token`, `vndb_auth_check`, `vndb_get_user_vn`,
  `vndb_set_status`, `vndb_set_vote`, `vndb_remove_vote`.
- **System/launch:** `launch_game`, `stop_tracking`, `poll_running_game`,
  `get_elapsed_time`.
- **Settings:** `get_settings`, `set_blur_nsfw`,
  `set_discord_rpc_enabled`, `set_discord_rpc_buttons`.
- **Wine (Linux):** `get_platform`, `get_available_wine_versions`,
  `refresh_wine_versions`, `get_default_wine_settings`,
  `get_default_prefix_path`, `save_game_wine_settings`,
  `save_global_wine_defaults`, `is_steam_runtime_available`,
  `validate_wine_binary`.
- **Logs:** `read_log_file`, `get_log_path`.

Shared state, managed via `.manage(state)` + `.manage(app_db)`: `AppState`
(running game, settings, VNDB mem caches, detected Wine versions, HTTP
client, Discord client) plus `AppDatabase` (`Mutex<Connection>`, the
games + cache store). All shared mutation goes through
`parking_lot::Mutex`-guarded state, SQLite statements, and atomic JSON
persistence.

Frontend consumes the contract only through generated `bindings.ts` types
plus the Tauri invoke layer in context providers. Adding a command
REQUIRES registering it in `collect_commands!`, adding its `.typ`
entries, and re-running a debug build to regenerate bindings.

### 6. Key Flows

- **Library UX:** grid/list `viewMode` toggle; sorting by name (`title`),
  most played (`playTime`), last played (`lastPlayed`) in asc/desc order;
  title search plus hidden-games toggle (`useLibraryFilters`, persisted
  via `@solid-primitives/storage`).
- **Launch + tracking:** `launch_game` validates the executable path,
  spawns via Wine/Proton runner or natively, records `RunningGame` with
  `Instant`, emits Discord activity, and on process exit calls
  `AppDatabase::add_playtime` (bumps `playtime_seconds`, stamps
  `last_played`, appends a `playtime_sessions` row) plus `daily_playtime`
  minutes. Emits a `game-exited` event with `{ game_id, play_minutes }`.
- **VNDB detail:** mem cache -> disk cache -> `POST
  https://api.vndb.org/kana/vn` (+ characters endpoint); `force_refresh`
  bypasses caches and re-persists both layers.
- **Wine detection (Linux):** `AppState` starts with an empty runner list
  so startup never blocks; a background thread scans Steam library roots
  (including secondary folders from `libraryfolders.vdf`),
  Lutris/Bottles directories, and `~/.wine`, then fills
  `wine_versions` (binaries classified into `WineType`/`WineSource`).
  Early runner queries may return empty until the scan lands;
  `refresh_wine_versions` rescans on demand. Non-Linux builds keep an
  empty runner list.
- **Discord RPC:** connect on launch when enabled; activity carries title,
  developer, cover, start timestamp, and optional VNDB/game/profile
  buttons; cleared when tracking stops.
- **Updater:** `useUpdater` hook against the GitHub `latest.json`
  endpoint; `UpdateDialog` prompts install via the updater + process
  plugins.

### 7. Security & Platform Targets

- CSP in `tauri.conf.json` restricts images to self/VNDB/data/blob and
  connects to VNDB + GitHub release hosts.
- Window is frameless (`decorations: false`, custom `TitleBar`), maximized
  by default, with GPU rasterization flags.
- Targets: Linux (Wayland/X11) and Windows; NSIS installer + updater
  artifacts; WixTools/NSIS bundler dirs gitignored.
- TLS: `reqwest` 0.13 uses `rustls` (platform verifier, no OpenSSL
  dependency from the app HTTP client).

### 8. Non-Functional Requirements

- Lightweight desktop client with fast startup; no bundled browser
  engine beyond the system webview.
- Offline-first library and launch flows; VNDB outages degrade to
  cached data with a clear English message.
- Responsive UI with consistent theme tokens (`src/index.css`
  `--color-*`: light surfaces, navy accent, success/danger/warning
  scales).

### 9. Roadmap

- Windows release hardening (single installer, updater signing rotation).
- Linux packaging (native binary, Flatpak/AppImage manifests).
- Launch robustness (missing-binary recovery, concurrent-launch guard).
- Cache maintenance UX (per-entry invalidation, size accounting).
- Playtime analytics on top of `daily_playtime.json`.

#### Proposed (NOT Current State, Requires Approval)

- Evaluate a frontend migration from SolidJS to React (icons already
  Tabler; swap `@tabler/icons-solidjs` for `@tabler/icons-react`).
- Evaluate adding a `tsc` typecheck gate to `npm run build`.
